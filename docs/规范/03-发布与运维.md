# 03 · 发布与运维

> 上位文件：[标准开发流程](../标准开发流程.md) §3、§8。
> 本项目当前为**本机运行的流程验证载体**，本文按此从简；**将来要给他人使用时，必须重写本文**（届时补：部署方式、数据备份、监控告警、SLA）。

## 1. 发布

- 前提：CI 绿（门禁第 1 条）。
- 步骤：见[分支与版本管理](01-分支与版本管理.md) §4——CHANGELOG 定版 → 去 SNAPSHOT → tag → push。
- 交付物：可运行的 jar（`mvn package` 产物）+ 对应 tag。

## 2. 回滚

- 代码回退：`git revert <提交>`——**禁止** `git reset` 改写已推送历史。
- 运行回退：停进程 → 换上一个 tag 的 jar → 启动；数据在内存中，回滚即恢复（引入存储后本节重写）。

## 3. 监控

- 环境健康：CI 每次提交自动构建+测试，失败即暴露（§1.6 的定位）。
- 运行状态：本机看进程与日志；接口可用性可用 `curl /api/products` 作最小探活。

## 4. 事件处理

任何运行问题（缺陷、环境故障）→ 回到迭代循环 §2.1，以缺陷单进入循环，走完全流程；紧急修复按总纲 §7 裁剪执行，48 小时内补文档与复盘。
