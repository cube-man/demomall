# 迭代 001 · 商品按名称搜索

## 需求（§2.1）

- **背景**：商品目录目前只有全量列表接口；需要一个按名称查找的能力。同时它是流程验证的第二个演示场景（第一个走完全循环的真实改动）。
- **要做什么**：新增接口 `GET /api/products/search?name=<关键字>`，返回名称**包含**关键字的商品列表（匹配不区分大小写）。
- **验收标准**（可逐条判断）：
  1. `name=键盘` → 200，返回 1 条：机械键盘
  2. `name=支架` → 200，返回 1 条：显示器支架
  3. `name=`（空值）或参数缺失 → 200，返回全部商品（与列表接口等价）
  4. `name=不存在的东西` → 200 + 空数组 `[]`（是"没找到"，不是 404）
  5. 现有 3 条商品数据不变，不新增预置数据
- **范围边界（明确不做）**：不做分页；不做拼音/同义词/分词匹配；不改动既有两个接口；不引入存储。

## 设计（§2.2）

**方案（已选定）**

1. `ProductService` 新增 `searchByName(String keyword)`：keyword 为空（null 或去空格后为空串）时返回全部；否则按 `名称.toLowerCase().contains(关键字.toLowerCase().trim())` 过滤，返回不可变列表。
   - 注意：**Java 8 没有 `String.isBlank()`**（那是 Java 11+），判空用 `trim().isEmpty()`——这是本改动最容易踩的兼容性坑。
2. `ProductController` 新增端点 `GET /api/products/search`，参数 `@RequestParam(required = false) String name`，复用既有 `toResponse` 转换。

**备选与取舍**

| 备选 | 否决理由 |
|---|---|
| 在既有列表接口上加过滤参数 | 需求边界明确"不改既有接口" |
| 新建独立的 SearchController | 同一资源的操作内聚在一个 Controller，拆开徒增跳转 |

**已知风险与对策**

- `/api/products/search` 与 `/api/products/{id}` 路由冲突？Spring MVC 精确路径优先于模板变量，`/search` 不会被当成 id；集成测试同时覆盖两条路径以证明互不干扰。

**影响范围**

- 新增：`searchByName` 方法、`/search` 端点、2 条测试
- 修改：`ProductService`、`ProductController` 各追加一段，**既有接口行为零变化**
- 不动：模型、DTO、pom、预置数据

**对外变化**：新增一个只读接口，其余接口无变化。

**需同步的文档**：README 接口表加一行；`docs/启动链/03-架构说明.md` 示例业务接口清单同步加一行（与代码同一批提交）。

**分支方式（已选定）**：走 `feat/product-search` 功能分支开发，§2.6 演示合并回 main——用真实合并动作演示流程，代价是稍多的两三条命令，值得。
